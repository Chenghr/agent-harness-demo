# 11-DeepSeek 适配与简单真实测试

这轮先用 DeepSeek 官方 API 验证小文件任务。你在网页填写密钥后，就可以按下面的步骤操作；不需要准备图片服务或发布网站。

## 这次补了什么

主任务、子助手、连接测试和宠物问答共用同一套模型历史保存方式。Chat Completions 收到的 `reasoning_content` 单独保存，后续请求同一模型、同一配置时原样带回；它不混入聊天正文。Responses 保留完整输出项，并按调用 ID 连接工具结果。关闭思考与开启思考分别适配，避免把 `none` 当成 Chat Completions 的思考强度直接发送。

压缩时将完整历史连同服务返回的状态一起归档，输入容量估算也计入这些内容。换模型或配置变化后，不复用旧配置的内部状态；模型交接继续保留可见记录、任务要求和工具结果。摘要与自动审批调整输出上限时，保留原先选定的服务连接，避免意外改用环境变量中的服务。

网页新增“DeepSeek 官方预设”。同时修复了网页添加的真实模型无法用于 Skill 独立评估和导入比较的问题。这些入口现在判断模型是否为真实且已配置，不再根据内部名称的前缀判断。

实现入口：[请求适配](../server/models.mjs)、[统一历史保存](../server/model-history.mjs)、[网页配置](../web/app/components/runtime-settings.tsx)。

## 先配置模型

打开 `http://127.0.0.1:4317/`，点击“模型与运行设置 → DeepSeek 官方预设”。只在网页输入密钥，先“保存服务”，再“保存模型”，最后点击模型旁的“测试调用”。保存后无需重启。

预设填写以下内容，可以在保存前修改：

| 配置 | 预设值 |
| --- | --- |
| API 地址 | `https://api.deepseek.com` |
| 协议 | Chat Completions |
| 模型 ID | `deepseek-flash` |
| 上下文上限 | `1000000` tokens |
| 单次输出上限 | `8192` tokens |
| 默认思考等级 | `none`，关闭思考 |
| 可选思考等级 | `none,low,high,max` |
| 输出参数 | `max_tokens` |

模型名称和 1M 上下文依据 2026-09-11 查阅的[官方模型说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。8192 是本应用用于起步测试的输出限制。模型列表不能验证容量；运行时还会从上下文容量中预留输出和估算余量。后续若服务规格变化，请按官方资料调整。

第一次先用 `none` 完成连接测试。通过后，可编辑模型，将默认思考等级设为 `high`，保存并再次测试，再改回 `none` 进行下面的小任务。Chat Completions 的开关与历史回传规则见[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。也可以另建使用 Responses 协议的服务配置测试同一模型；这属于协议切换，不代表换成了另一种模型。[官方 Responses 说明](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)

“测试调用”实际完成两次模型请求：模型请求一个无副作用的测试工具，接收工具结果，再回答。最多等待两分钟。通过仅证明连接与这一轮工具协议可用；后面的真实任务仍需逐项核对。测试失败时先核对密钥、账户余额、模型 ID 和协议，页面不会自动换成模拟模型。

## 准备三条小样本

在 macOS 终端执行一次，保持这个终端供后面检查文件使用：

```sh
export HARNESS_QUICK_ROOT="$(mktemp -d "${TMPDIR:-/tmp}/harness-deepseek.XXXXXX")"
node --input-type=module <<'NODE'
import fs from 'node:fs';
import path from 'node:path';
const root = process.env.HARNESS_QUICK_ROOT;
const batches = {
  'batch-a.json': [
    { id: 'A1', text: '演示联系人甲的邮箱是 alpha@example.test。' },
    { id: 'A2', text: '这条演示材料没有邮箱。' },
  ],
  'batch-b.json': [
    { id: 'B1', text: '演示联系人乙的邮箱是 beta@example.test。' },
  ],
};
for (const [name, content] of Object.entries(batches)) {
  fs.writeFileSync(path.join(root, name), JSON.stringify(content, null, 2) + '\n');
}
console.log('网页中添加这个工作区：' + root);
NODE
```

在工作台点击“添加目录”，把终端输出的绝对路径填进去，点击“添加此路径”，选中该工作区。模型选择刚保存的 DeepSeek，权限先选“请求批准”。这三条都是合成材料；本次只提取邮箱，不设计完整标注标准。

## 逐条测试

每一步先检查结果，再继续下一步。普通文件任务显示“待验收”时，由你核对后确认；模型说完成并不替代文件检查。录屏可同时展示对话和“运行详情”，密钥填写提前完成。

### 1. 读取与连续工具调用

发送：

```text
只读检查当前工作区。先列出文件，再分别读取 batch-a.json 和 batch-b.json。
告诉我每个文件有几条样本、哪些样本包含邮箱。不要写文件，不要联网，不要创建助手。
```

检查“运行详情 → 工具”：应有实际文件读取记录。正确结果是 A 批次 2 条、B 批次 1 条；A1、B1 包含邮箱，A2 没有。这一步验证真实模型能根据工具结果继续执行，不能只看它是否回复了文字。

### 2. Skill 分层发现与加载

在同一对话发送：

```text
通过能力目录逐层查看与隐私数据检查有关的方法，找到并加载 privacy-boundary。
说明它有哪些规则适用于刚才的三条样本，以及哪些规则这次不需要用。
不要修改文件，也不要为了找方法加载整个目录。
```

检查实际目录浏览和 `skill_load` 记录。方法加载后可以看到固定的版本及已加载内容。若模型没有找到，记录实际停在哪一级；不要把“说自己加载了”算作通过。

### 3. 两个后台助手

继续发送：

```text
创建两个后台分析助手：第一个只分配 batch-a.json，第二个只分配 batch-b.json。
各自读取分配文件，返回样本 ID、找到的邮箱和无邮箱样本；各自不超过 100 字。
不分配其他文件，不写文件。创建后先告诉我分工，再等待结果并汇总，不重复创建助手。
```

检查任务树里两个助手的父任务、实际模型和文件范围；各自工具记录应只读取分配文件。主助手拿到结果后应汇总出 `alpha@example.test`、`beta@example.test`，并保留 A2 是空样本这一事实。任务太快时，可以用录屏回看创建与完成事件。

### 4. 写文件、局部修改、撤销

发送：

```text
依据实际读取结果生成 emails.json，内容为数组，每项只有 id 和 emails 两个字段。
保留 A1、A2、B1，A2 的 emails 必须是空数组。只写 emails.json，不改两个输入文件。
写完后重新读取 emails.json，逐项核对再回复。
```

在终端检查真实文件：

```sh
cat "$HARNESS_QUICK_ROOT/emails.json"
```

核对三条样本和两个邮箱后，在同一对话追加：

```text
只把 emails.json 中 A1 的 emails 改为空数组；其他样本以及两个输入文件保持不变。
改后读取文件确认。这是一次局部修改演示。
```

等待执行结束，打开“修改记录”，选择这次局部修改所在的一轮，仅撤销 `emails.json`。再运行上面的 `cat`：A1 的邮箱应恢复，A2、B1 不变。回滚保留对话记录，后续模型需要重新读取文件。

“请求批准”模式下，普通工作区内写入按现有规则直接执行；本步骤验证写入和回滚，不要求每次写文件弹出审批。审批单独在下一步验证。

### 5. 批准与停止

发送：

```text
使用 shell_run 在当前工作区运行下面这一条命令，保持默认受限访问：
node -e "setTimeout(() => console.log('等待结束'), 20000)"
不要修改文件或联网，也不要创建子助手。
```

在待审批卡片核对命令并批准；看到执行进程开始后点击“停止”。检查任务停止、进程资源回到 0，没有把被取消的命令标为成功。这个等待只为了留出手动操作时间。它测试终端审批与执行取消；完整的三种权限模式仍可按第 10 份手册测试。

### 6. 压缩后继续与配置交接

继续同一对话，明确要求先处理历史：

```text
继续处理这三条样本。先调用 context_compact 整理较早的完整交互，再重新读取 emails.json。
告诉我原始样本数、哪些样本有邮箱，以及现在文件中的实际内容。不要重复写入。
```

在“运行详情 → 上下文”检查压缩次数、摘要和原文入口，再与文件核对。历史太少、候选摘要没有缩小内容时，系统可以明确跳过；跳过不算压缩成功。可先追加几次针对实际文件的检查，再测试。不要把小任务的手动压缩讲成已经实测 1M 输入。

如要演示切换，在“添加模型”旁点击“添加另一个”：所属服务选已保存的 DeepSeek，其余模型字段按上表填写，显示名称改为“DeepSeek · 思考”，默认等级选 `high`。保存并测试调用后，在主对话模型选择器中切换到它，再发送：

```text
根据已有记录，说明本次做过哪些文件修改、哪次已撤销。必要时读取文件核对；不要重新执行写入。
```

检查交接记录和文件未被重复修改。这验证两份配置之间的交接，不能声称比较了两个不同基础模型的能力。若需要真正换基础模型，另行填写账户可调用的不同模型 ID。

### 7. 宠物与独立管理评估

打开宠物，发送“查一下这段任务的历史，告诉我目前检查了什么、哪些操作已经撤销”。检查它确实检索了历史，有不确定之处如实说明；主对话没有因此新增执行指令。点击外侧“太慢了”或鸡蛋，观察即时反馈。

打开“能力管理”，在“独立评估模型”中选择网页保存的 DeepSeek。找到 `privacy-boundary`，分别发起质量评估和安全评估，在“评估记录”查看结果。检查质量分的原文依据与独立安全结论；模型输出格式或证据不合格时应看到失败，不能用默认分数冒充评估完成。
