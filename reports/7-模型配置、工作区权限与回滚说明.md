# 7-模型配置、工作区权限与回滚说明

本轮将已有的课程框架接到实际的本地文件任务上，新增网页模型配置、用户工作区、三种权限模式、Git 修改记录与撤销，并调整桌面小伴的快捷反馈。原有任务控制、Agent Loop、子助手和能力管理继续复用。前两份核心说明没有改动。

## 网页配置模型

从左下角“模型与运行设置”添加服务，填写名称、API 根地址、协议和密钥。再添加具体模型，填写模型 ID、上下文上限、输出上限、支持的思考等级与默认等级。当前支持 Responses 和 Chat Completions 的文本与工具调用；兼容服务可选择 `max_tokens` 或 `max_completion_tokens`。不把填写能力当作服务已经通过验证。

服务和模型分别保存，不同服务不再共用一套地址或密钥。“获取模型列表”通过提供方的 `/models` 发现名称；没有此接口时可以手动填写。列表不保证包含上下文等能力信息，这些信息仍按服务文档填写。

“测试调用”验证一次工具请求、工具返回和最终回答，显示耗时和失败原因。它不验证模型最大上下文，更不等同于实际任务质量测试。保存配置后无需重启，后续请求使用新配置；已经发起的请求固定使用当时的连接参数。Responses 的内部响应只在同模型、同配置版本下续用。

密钥与普通模型信息分开保存于应用数据目录，凭据文件权限为 0600，只允许当前系统用户读写。当前采用本地文件保存，尚未接 macOS 钥匙串，也没有宣称加密保存。网页不回读明文密钥，任务上下文和工作区 Git 不保存密钥。原有 `.env` 接入仍兼容。

实现入口：[模型设置](../server/settings/models.mjs)、[设置接口](../server/settings/routes.mjs)、[模型请求适配](../server/models.mjs)。

## 工作区与权限

首页可以添加本地目录，macOS 提供文件夹选择入口，也可以输入绝对路径。普通目录和已有 Git 仓库都能使用。对话创建后固定绑定工作区；切换目录将进入新任务入口，不会移动正在执行的任务。为避免多段对话混写，本轮对相同或相互包含的目录实行单任务占用，执行结束后释放。

权限入口在输入框下方，按当前对话生效。教学示例保留原来的示例审批逻辑，以下三种模式用于用户工作区。

| 模式 | 实际行为 |
| --- | --- |
| 请求批准 | 工作区内普通读取、写入和精确替换直接执行；删除、终端命令、工作区外文件操作请求用户批准。 |
| 帮我批准 | 工作区内需要审批的操作交给独立的模型请求审查。审查者没有执行工具，不借用主任务的回答结果作为授权。结论为允许、拒绝或询问用户；服务不可用、超时或格式不正确时交还用户。工作区外操作和完整访问命令仍交给用户。 |
| 完全访问权限 | 经界面明确确认后，当前对话不再逐次审批。终端可使用本机文件和网络，仍受操作系统权限限制；macOS 命令额外隔离应用自身的数据目录。工作区外修改不在回滚范围内。 |

批准仅绑定当前具体操作，修改参数不能复用旧批准。切换权限会撤销旧授权，使待处理和排队中的旧操作失效；它不能撤回已经发生的副作用。子助手仍保留原有的分配材料和输出目录边界，不能因为主任务选了完全访问而自动获得整台电脑权限。

新增 `file_search`、`file_edit`、`file_delete` 和 `shell_run`。真实工作区的文件列表可遍历子目录；精确替换要求原文唯一匹配。凭据路径、应用记录与 Git 内部目录不会通过这些文件工具开放。模拟模型在用户目录中只提示配置真实模型，不执行购物车等教学脚本。

默认终端执行使用 macOS Seatbelt，限制工作区外写入与网络，保留必要的系统读取。需要更大范围时，模型必须以 `access: full` 明确申请单次完整访问，用户批准只作用于这一条命令。其他系统尚未实现受限命令沙箱，会明确拒绝这一执行方式；完全访问模式可使用系统已有 shell。本轮没有实现远程多人服务、系统管理员提权或对所有恶意程序的完整防御。

实现入口：[权限检查](../server/permissions.mjs)、[通用工作区工具](../server/workspace-tools.mjs)、[进程回收](../server/runtime/process-manager.ts)。

## Git 记录与撤销

每个工作区关联一份应用管理的本地 Git 存储，不需要 GitHub。检查点独立于用户项目，不修改项目分支、暂存区或提交历史。对话开始执行前保存基线；后续输入被控制器接收时形成下一段执行记录。同一批被接收的补充要求共同构成一个执行段。

每轮保存开始前和结束后的版本，完成、停止、失败都会保留已经产生的文件修改。普通文件工具逐次登记实际修改的路径和内容；用户在执行期间修改其他文件，不会被归入模型修改。如果将要写的文件已被外部修改，操作拒绝覆盖。终端命令以命令执行前后差异登记修改；命令运行期间若人也编辑同一个文件，系统无法可靠区分两者，因此同一时间不要手动改动命令正在处理的文件。

在对话右上角打开“修改记录”，可以查看文件前后内容并撤销指定一轮。撤销前检查全部目标文件，任意文件出现后续修改时报告冲突，不覆盖这些修改。任务和进程仍在运行时不能撤销。成功后保留聊天记录，清除旧的完成判断和活跃执行上下文，要求后续模型重新读取文件。

检查点遵守 `.gitignore`，跳过凭据、依赖、构建目录和符号链接；目前限制单文件 10 MB、总文件内容 100 MB、候选文件 10000 个。超限会明确失败。未记录文件、工作区外文件和外部 API 副作用不能通过这里恢复。Git 不记录空目录。撤销前另存一份 Git 备份；中途磁盘故障或服务崩溃留下的部分撤销不自动重放，需要依据保留的备份核对恢复。

实现入口：[工作区与 Git 检查点](../server/workspaces.mjs)、[修改记录界面](../web/app/components/workspace-changes.tsx)。

## 小伴的快捷情绪反馈

宠物外侧常驻点赞、点踩、鸡蛋和“太慢了”四个按钮，收起聊天面板也能使用。点击立即改变表情或播放短动画，不等待模型响应。没有关联任务时只提供互动效果，不给某个回答强加标签。

有关联任务时，反馈绑定当前任务，保留模型、执行状态、最近操作和经过时间。短时间内重复点击合并为一次反馈并累计次数。展开面板仍可以选择具体回答或工具操作，补充原因、导出或清空本地记录。这些都是情绪软标签，不直接判断模型质量，也不会自动停止任务、改变模型或上传训练数据。

## 验证与使用边界

新增测试覆盖独立服务配置与密钥不回传、模型发现和工具往返、原有 Git 草稿保护、回滚冲突、执行期间的手动修改、权限失效、自动审查失败回退、符号链接绕行、命令停止后的资源回收和部分输出撤销、重复情绪反馈合并。本轮完整测试 145 项通过，类型检查、lint、前端构建与 macOS 桌面编译通过。结果见 [本轮测试记录](usability-tests.txt)。

浏览器验收使用单独工作区和明确标注的本机协议测试服务，检查网页保存配置、测试调用、选择目录、修改文件、前后版本展示和撤销后的文件核对，并复查窄窗口中的设置与历史对话入口。没有使用用户真实密钥，因此真实供应商可用性和实际任务质量仍需由配置后的任务验证。本轮主要面向 macOS 的个人本地使用。
