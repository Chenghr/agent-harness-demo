# Harness 前端 UI 精致化改造方案

## 1. 设计目标

本次改造定位为“可信赖的 Agent 运行控制台”，关键词是：克制、清晰、可追踪、可打断、有层级。

改造只发生在前端表现层与组件组织层，不修改后端路由、DTO、SSE 事件协议、任务状态机、权限规则、工具执行和资源回收逻辑。

### 目标

- 第一眼能看懂当前任务是否安全、是否运行、谁在执行、是否需要用户处理。
- 把主 Agent、SubAgent、Supervisor 管控关系变成界面主叙事，而不是藏在信息密集的卡片里。
- 提升视觉质感，同时避免“渐变堆砌”和过度动效影响专业感。
- 在 1280×720 的录屏与 PPT GIF 中仍能清楚展示关键状态。
- 保留现有功能入口、键盘行为和无障碍名称，避免破坏手册与自动化测试。

## 2. 当前界面诊断

### P0：影响理解的主要问题

1. 页面大面积使用纯白和近似灰绿色，导航、聊天、运行观察三个区域的层级不够明显。
2. 多数状态共用相近颜色，“运行中、等待授权、停止、成功、失败”无法快速区分。
3. 运行观察面板只有约 360px，任务目标、权限、材料和操作按钮容易换行拥挤。
4. Agent 卡片偏“信息列表”，父子归属、后台执行、权限继承和资源回收关系不够直观。
5. 顶栏入口较多，运行详情、成果、图片与网站、能力目录的优先级相似。
6. 输入区的“目标 Agent、追加/改方向、权限模式、模型”分散，任务发送前不容易确认作用对象。
7. 小伴悬浮区域会遮挡右侧面板和录屏关键内容。
8. `page.tsx` 超过 2,000 行，`globals.css` 接近 2,000 行且存在后置覆盖，视觉修改容易产生回归。

### 保留的优点

- 三段式结构符合 Agent 控制台心智：任务列表、对话执行、运行观察。
- 任务树、工具、上下文、事件、产物五个观察维度完整。
- 当前配色克制，适合沿用灰绿品牌基因，而不是彻底更换风格。
- SSE 实时状态与现有无障碍标签已经为精细反馈提供了良好基础。

## 3. 总体视觉方向

### 设计概念：Quiet Operations Console

整体采用“暖灰工作台 + 白色操作面 + 深墨绿品牌色”的专业控制台风格。背景负责分区，品牌色只用于主要动作和运行态，状态色只用于语义反馈。

### 颜色系统

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#F3F5F2` | 应用背景 |
| `--surface` | `#FFFFFF` | 主内容与卡片 |
| `--surface-subtle` | `#F8FAF7` | 次级面板、输入区 |
| `--ink` | `#182019` | 主文本 |
| `--ink-secondary` | `#657066` | 次级文本 |
| `--border` | `#E1E6DF` | 普通边界 |
| `--brand` | `#3F5F4C` | 主按钮、选中态 |
| `--brand-soft` | `#E9F0EB` | 品牌浅底 |
| `--running` | `#287C72` | 运行、实时连接 |
| `--success` | `#3E7A4C` | 完成、验收通过 |
| `--warning` | `#B07824` | 等待授权、待验收 |
| `--danger` | `#B14E45` | 失败、拒绝、停止动作 |
| `--neutral` | `#7B847C` | 已停止、闲置 |

状态不只依靠颜色：同时使用图标、文字和圆点/进度形态，保证色觉障碍用户可识别。

### 字体与排版

- 不增加在线字体依赖，使用 `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", sans-serif`。
- 标题使用 600 字重，正文 400/450，控制台数据使用等宽字体。
- 正文基准 14px；辅助文本 12px；指标数字 24–28px。
- 统一 4px 基础间距，常用间距为 8/12/16/24/32。
- 圆角分为 8px（控件）、12px（卡片）、16px（浮层），避免全站每处不同。

### 阴影与动效

- 只在悬浮输入框、弹窗和抽屉使用阴影；普通卡片以边框区分。
- hover/focus 120–160ms，面板展开 180–220ms。
- 运行态只让一个 6px 指示点呼吸，不让整张卡片闪烁。
- 支持 `prefers-reduced-motion`，保持现有无动效降级逻辑。

## 4. 信息架构与页面布局

### 桌面端三栏

| 区域 | 宽度 | 作用 |
| --- | --- | --- |
| 左侧任务栏 | 232–248px，可折叠至 72px | 工作区、页面导航、任务历史 |
| 中间主工作区 | `minmax(560px, 1fr)` | 对话、审批、任务输入 |
| 右侧运行面板 | 默认 420px，可缩放 360–520px | Agent 树、工具、上下文、事件、产物 |

建议使用仓库已经安装的 `react-resizable-panels`，仅保存前端面板宽度到 localStorage，不向后端提交。

### 响应式

- `≥ 1280px`：完整三栏。
- `1024–1279px`：左栏缩为 208px，右栏 380px。
- `768–1023px`：左栏折叠；运行观察改为右侧抽屉。
- `< 768px`：单列；任务列表与运行观察均为全屏 Sheet；底部输入区固定。

### 顶栏重排

顶栏只保留三类信息：

1. 左侧：任务标题 + 当前工作区。
2. 中间/右侧：实时连接状态、任务状态。
3. 主要动作：运行观察、成果；其余入口放入“更多”菜单。

“停止整个任务”在运行时固定为可见的危险操作，不藏入更多菜单。

## 5. 核心区域详细设计

### 5.1 左侧任务栏

- 品牌区高度缩至 64px，使用更简洁的 Harness 图标和产品名。
- “新建任务”保持唯一高强调按钮。
- 最近任务按“运行中 / 待处理 / 最近”分组；标题最多两行。
- 每个任务展示语义状态点和更新时间；运行中任务显示微弱动态点。
- “能力管理、快速加载、设置”统一图标规格与选中态。
- 本地运行说明改为底部可信标识，不占据主要视觉注意力。

### 5.2 新建任务空状态

- 收紧无意义留白，把标题、说明、示例任务和输入框形成一个视觉整体。
- 默认展示 3 个高价值场景卡片，不需要先点击“试试一个演示任务”才能发现。
- 场景卡片增加能力标签，例如“SubAgent”“权限回收”“上下文压缩”。
- 页面右上保留“Demo 模型”标记，但降低视觉权重。

### 5.3 对话与运行消息

- 主 Agent 消息使用无气泡排版，保持长文本阅读效率。
- 用户消息使用浅色气泡并右对齐，快速区分输入与执行结果。
- 系统/运行时消息改为细时间线样式，而不是与普通消息等权。
- 工具调用折叠成单行 Activity Row：图标、工具名、状态、耗时；点击查看参数与结果。
- 长任务增加阶段分隔：理解任务、规划、执行、验收。
- 时间默认弱化，hover 后显示；错误、审批、验收卡片始终可见。

### 5.4 输入区 Composer

输入框上方增加“发送对象条”：

- `主 Agent` / 指定 SubAgent。
- `补充要求` / `按新方向继续`。
- 当前权限模式。

输入框下方保留模型选择和发送按钮。运行中时，停止按钮与发送按钮并列但采用危险色描边，避免误触。

键盘行为保持不变：Enter 发送，Shift+Enter 换行。

### 5.5 运行观察面板

面板顶部改为“状态总览”，展示：

- 当前阶段与连接状态。
- 工具调用数、后台任务数、上下文占用、存活资源数。
- 运行时显示耗时；完成后显示总耗时。

五个页签保留原值和功能，视觉上改为紧凑 Segmented Tabs，并固定在面板顶部。

### 5.6 Agent 任务树（重点）

Agent 卡片分为三层信息：

1. 身份层：主 Agent / 分析助手 / 检查助手、模型、状态。
2. 任务层：目标摘要、运行模式、轮次。
3. 边界层：工作区权限、分配材料、允许工具、资源状态。

建议视觉结构：

```text
主 Agent                         运行中
业务决策 · Demo 标准
│  工具 8   子任务 1   权限：请求批准
│
└─ 分析助手                     后台执行
   检查购物车数量、折扣和空输入边界
   [只读] [cart.mjs] [2 个工具]   轮次 2
```

- 父子卡片使用清晰的树连接线，而不是只靠左缩进。
- 权限采用 Badge：`只读`、`可写 outputs`、`已撤权`。
- 材料和工具默认展示摘要，展开后查看完整内容。
- 子任务运行时提供“补充、改方向、取消”三项操作；危险操作与普通操作分色。
- 任务取消后展示“已沿任务树停止”“资源已回收”，形成完整的生命周期闭环。
- 若 `a.stale` 为真，使用警告色提示“依据已变化”，不能只放在 details 文本中。

### 5.7 权限与审批

- 审批卡片使用暖黄色语义边框，顶部明确展示“谁申请、申请什么、影响哪些路径”。
- 将 `task / once / deny` 翻译为更可理解的动作：本任务允许、仅本次允许、拒绝。
- 完全访问权限继续使用二次确认弹窗。
- 子 Agent 的权限说明直接复用后端返回的 delegation 数据，不在前端推断或提升权限。
- 运行时撤权后，Agent 卡片立即切换为 `已撤权` 状态并禁用相关动作。

### 5.8 工具、上下文、事件与产物

- 工具：已加载定义与最近调用分区；成功/失败/取消使用清晰图标和耗时。
- 上下文：使用单一进度环或进度条，显示已用、预留、可用；压缩记录用时间线。
- 事件：支持按 Agent 和事件类型筛选，默认隐藏模型 delta 与进程输出等噪声。
- 产物：用文件类型图标、大小、创建者和状态展示；成果入口仍调用现有下载/查看接口。

### 5.9 小伴 Companion

- 默认收纳为右下 44px 图标，只有用户主动打开才展开。
- 当运行观察面板打开时自动向左避让，不覆盖按钮或 Agent 卡片。
- 增加“演示模式”前端开关：录屏时隐藏快捷表情与气泡，但不停止 companion 后端能力。

## 6. 前端组件重构建议

不建议继续在 `web/app/page.tsx` 和 `web/app/globals.css` 中叠加覆盖。建议按表现职责拆分：

```text
web/app/components/workbench/
  app-shell.tsx
  task-sidebar.tsx
  task-header.tsx
  conversation-pane.tsx
  message-item.tsx
  task-composer.tsx
  runtime-inspector.tsx
  agent-tree.tsx
  agent-node-card.tsx
  runtime-metrics.tsx
  approval-card.tsx

web/app/styles/
  tokens.css
  shell.css
  conversation.css
  inspector.css
  states.css
```

### 数据边界

- 保留 `Session`、`Agent`、`Action`、`Approval`、`EventItem` 等服务端 DTO 结构。
- 新增纯前端 selector/view-model 函数，例如 `selectActiveChildren(session)`、`toAgentNodeView(agent)`。
- view-model 只格式化文本和视觉状态，绝不改变后端值或拼造权限。
- 把 `api()` 与 EventSource 订阅抽到 `useHarnessSession()`，保持调用路径和事件监听名称不变。

## 7. 后端兼容性红线

以下内容必须保持原样：

- `/api/config`、`/api/sessions`、`/api/sessions/:id/*` 等请求路径与 HTTP 方法。
- `/api/sessions/:id/stream` SSE 连接及 `state`、`event` 事件名称。
- `Session`、`Agent`、`delegation`、`resources`、`completion` 等字段含义。
- `activeStates` 与所有任务状态值，不以 UI 文案代替后端枚举。
- 创建任务、追加消息、steer、停止、审批、创建/取消子任务、模型切换、产物读取等 command 路由。
- 权限判断仍由后端执行；前端只能展示和发起请求。
- 现有 aria-label 和关键按钮名称尽量保留，防止手册和 UI 自动化失效。

推荐先建立一份 `frontend-contract.ts`，只从当前服务端 contracts 导入类型，避免改造过程中复制并漂移 DTO。

## 8. 实施顺序

### Phase 0：基线与保护（0.5 天）

- 固化主要页面截图和手册场景。
- 记录全部 API/SSE/command 路由。
- 为新建任务、启动、SubAgent、停止、审批、产物增加前端冒烟测试。

### Phase 1：设计 Token 与页面骨架（1 天）

- 建立颜色、间距、圆角、字体、阴影和状态 Token。
- 完成三栏、响应式、顶栏和侧栏调整。
- 不改业务组件内部逻辑。

### Phase 2：对话与输入区（1–1.5 天）

- 重构消息、运行时提示、审批卡片和 Composer。
- 保持 send/create/command 调用不变。

### Phase 3：运行观察与 Agent 树（1.5–2 天）

- 重构指标、Tabs、Agent Node、权限 Badge 和资源区。
- 增加面板缩放与宽度本地记忆。

### Phase 4：能力、成果、弹窗与小伴（1–1.5 天）

- 统一能力管理、交付、设置弹窗的视觉语言。
- 修复小伴遮挡并增加演示模式。

### Phase 5：回归和录屏（1 天）

- 执行 build、lint、关键流程与手册回归。
- 检查 1440×900、1280×720、1024×768、390×844。
- 重新录制 1280×720 或 1440×810 高清 GIF。

预计总投入：5–7 个前端工作日。

## 9. 验收标准

### 视觉

- 1280×720 下主任务、子任务、状态和停止按钮无需滚动即可同时出现。
- 正文和状态文字满足 WCAG AA 对比度。
- 小伴不遮挡输入区、任务树和主要动作。
- 同一种状态在任务列表、对话、Agent 树和事件列表中颜色与文案一致。

### 功能回归

- 新建自定义任务和全部内置 Demo 均可启动。
- SSE 断开/重连状态正确展示。
- 用户补充、steer、停止整个任务可用。
- 主 Agent 创建 SubAgent、对子任务补充/改方向/取消可用。
- 权限审批三种决策可用，完全访问仍需确认。
- 模型切换、工具加载、Skill 加载、上下文压缩、成果验收、产物查看可用。
- 停止任务后后台活动为 0，存活资源为 0。
- 能力管理、图片与网站、修改记录、小伴功能不回归。

### 工程质量

- `npm run build` 和 `npm run lint` 通过。
- 浏览器控制台无新增 error。
- 不新增后端文件变更，不改变 API 返回结构。
- 手册中的核心按钮仍可通过原有可访问名称定位。

## 10. 推荐首批落地范围

首批先改“工作台首页 + 运行观察 + Agent 树 + Composer + 小伴避让”。这部分最直接提升产品观感，也最适合重新录制 Harness 特性 GIF。能力管理和交付页面放在第二批统一，能够降低一次性改动范围和回归风险。
