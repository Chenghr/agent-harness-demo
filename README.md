# Harness · 工作空间

用于课程展示的本地 Web Demo。简洁的中文工作台配合按需展开的运行详情与桌面小伴，展示一个自行实现的 Agent Harness 如何管理模型之外的执行过程。

默认无需 API Key。模拟模型负责产生可复现的决策序列；文件操作、Node 测试、进程取消、授权检查、上下文管理和事件记录都经过同一套真实运行时。

## 启动

需要 Node.js 24.12+。新核心使用 TypeScript，由 Node 原生去除类型后执行，开发时另行运行严格类型检查；后端无需额外构建。当前验证环境为 macOS；进程组管理以 macOS / Linux 为目标。

在项目根目录运行：

```bash
npm ci
npm --prefix web ci
npm run build
npm start
```

打开 **http://127.0.0.1:4317**。首次安装依赖需要网络；构建完成后，模拟模式可离线使用。交付目录若已经包含 `dist/`，执行 `npm ci` 安装后端依赖后即可 `npm start`，不需要重新构建前端。后端使用 Node 内置模块、YAML 解析器和 Ajv 参数校验。

开发时使用 `npm run dev`，打开 **http://127.0.0.1:4318**。此模式同时启动 4317 后端和 4318 前端，前端支持热更新；后端文件修改后需要重启。不要同时启动开发模式和正式模式，以免端口冲突。按 Ctrl+C 会关闭服务并取消受管理任务。

## 桌面小伴

先运行 `npm start`，再在另一个终端执行 `npm run desktop`。macOS 上会用 Swift 编译并启动 `.desktop/HarnessPet.app`，支持桌面浮窗、任务进展、独立对话、只读历史检索和点赞／点踩／鸡蛋反馈。菜单栏可隐藏或退出。需要 Swift 编译器；`npm run build:desktop` 只编译。

浏览器右下角也有同一只小伴。`/pet/` 是独立网页，可跟随工作台或固定查看任务。模拟模式只显示进展与检索结果，配置真实模型后才能自由解释与聊天。反馈只在本机保存，可导出或清空；真实模型请求仍会将必要材料发送到所配置服务。

## 已提供的功能

| 课程要求 | 当前 Demo |
| --- | --- |
| 自行实现 Agent loop | 模型请求、流式输出、工具交互、状态更新、预算与终止 |
| 成果检查与验收 | 执行收尾后按任务标准检查；失败反馈并有限返工，未知结果待用户验收 |
| 用户打断 | 立即改方向、下一步补充、停止整个任务；旧轮次输出不能继续派发工具 |
| 子助手协作 | 临时通用任务与可配置专门助手、指定材料、前台等待或后台执行、权限限制、结果去重和进程回收 |
| 工具发现与加载 | 1,223 个初始目录条目，多层发现、固定版本加载、严格参数校验与卸载 |
| Skill 加载 | 1,207 份初始方法包，整包版本、容量预检、资源分页和已确认的分阶段加载 |
| 能力管理 | 独立页面，导入和批量冲突处理、目录概述、来源标注、质量与安全分别评估 |
| 上下文压缩 | 按模型窗口分配容量，模型摘要或可追溯节选；验证后提交，保留原文 |
| 模型切换 | 手动请求，在完整工具交互结束后交接；检查目标窗口，失败保留原模型 |
| 安全性 | 按助手限制材料与工具、真实路径检查、独立输出、按助手和文件授权、撤销与过期批准拒绝 |
| 可靠性 | 可取消队列、分离模型/执行并发、进程超时与回收、事件落盘、重连与重启标记 |
| 趣味性 | Web 与 macOS 桌面宠物、独立聊天与历史解释、软标签反馈、安静陪伴 |

规模数字的含义：22 个本地核心工具和 1 个固定命令工具，加上 1,200 个具有独立名称与定义的生成计算工具；7 个编写的 Skill，加上 1,200 个生成 Skill。生成工具按领域、指标、计算方式组合，复用聚合计算实现，不代表接入了 1,200 个外部服务。1,000+ Skill 指目录容量和累计加载能力，不是同时放入一次模型上下文。

匹配原始要求的隐私实体合成示例、完整任务链、安全反例和千次调用场景配置了自动成果检查。自由任务、分析场景和改变过要求的任务默认显示“待验收”；用户可以确认成果，或填写修改要求继续。后台助手的待核实结果会交回主助手。已明确失败的检查不能直接点通过，旧任务也不会自动补做成果验收。

助手配置位于 `config/agents/`：默认 `general` 可接受临时任务并申请生成独立产物，`analysis` 和 `review` 限制模型文件写入。配置只在后端启动时读取，工作目录中的文件不能替代它。详细规则见第二份说明。

## 接入真实模型

优先使用网页左下角“模型与运行设置”：先保存 API 服务，再添加模型 ID、上下文及输出上限，最后点击“测试调用”。保存后无需重启。不同服务可以使用不同地址和密钥，凭据只写入本机独立文件，不回传网页。

也兼容环境变量：复制 `.env.example` 为项目根目录的 `.env`，只在本机填写密钥，再重启后端。不要将 `.env` 交给其他人或提交到版本库。

```dotenv
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=在本机填写
LLM_MODEL=你的工具调用模型名称
LLM_MODEL_ALT=另一个兼容模型名称
LLM_PROTOCOL=responses
LLM_CONTEXT_WINDOW=32768
LLM_MAX_OUTPUT=2048
LLM_CONTEXT_WINDOW_ALT=
LLM_MAX_OUTPUT_ALT=
```

`LLM_PROTOCOL` 支持 `responses` 和 `chat-completions`。Base URL 填 API 根地址，程序会追加 `/responses` 或 `/chat/completions`。环境变量中的 A、B 共用服务地址、密钥和协议，窗口与输出上限可分别设置；网页配置的服务与模型相互独立。

窗口和输出预算必须按实际模型修改，默认值只是演示配置。仅在服务支持时填写 `LLM_REASONING_EFFORT`。接入模型需支持流式文本和函数调用；网页可选择兼容服务使用的输出参数；其他协议差异仍需适配。选真实模型时不会静默回退到模拟模型。

本次没有用户密钥，**真实 API 仅通过模拟 HTTP/SSE 的协议测试，未完成真实服务联调或回答质量评测**。两个 Demo 模型是同一个确定性模拟器的不同窗口配置，用于展示交接机制，不代表两种模型能力比较。

## 验证

```bash
npm test
npm run test:core
npm run typecheck:runtime
npm run test:scale
npm run lint
npm --prefix web exec -- tsc --noEmit -p web/tsconfig.json
npm run build
```

`npm test` 包括运行时、进程、权限、目录、压缩、切换、模型协议与 HTTP/SSE 集成测试。测试使用独立临时目录，不修改网页中的已有任务。

`npm run test:core` 单独运行新的控制器、循环和消息竞态测试。`npm run typecheck:runtime` 检查 TS 核心及其单元测试；检查工具复用前端已安装的 TypeScript，需要先执行 `npm --prefix web ci`。现有 `.mjs` 适配层尚未全部迁移到 TS。

`npm run test:scale` 先通过完整 loop 执行 1,005 次模拟数据工具计算，再逐项验证 1,200 个不同工具的加载/调用/卸载和 1,207 个 Skill 的加载/卸载，写入 `reports/scale.json`。这验证调度与容量，不证明真实模型能可靠规划千步任务，也不代表千级并发。

启动 `npm start` 后，可另开终端运行 `npm run test:smoke`，验证静态页面资源、HTTP 完整任务链和模型交接。该脚本会创建一个独立的自检任务，并仅自动批准该任务对示例 `cart.mjs` 的修改。

## 能力管理页面

在工作台左侧点击“能力管理”，进入 `/capabilities/`。先按“隐私实体数据集构建 → 标注检查”查看三份示例方法；初始教学规模样本单独放在另一个场景中。

导入时选择单份 Skill 文件夹，或包含多个 `SKILL.md` 子目录的集合。材料先进入待处理区，确认分类及冲突处理后才启用。支持多分类、批量处理、用途相近候选、可选真实模型比较及人工关系确认。工具定义导入后仅供审查；实际命令通过仓库内 `config/tools/` 可信配置登记，MCP 尚未接入。

质量和安全分别发起评估。未配置真实模型时仍能扫描，但不会制造五级分数或完整安全结论。完整分数要求六个维度全部覆盖且证据可核实；长文件分段阅读后，尚未完成的跨段判断会显示缺口。模型评估只接收选中的能力材料，不读取业务对话，也不执行其中脚本。

`npm run test:capabilities` 验证本轮导入、目录、报告、加载与 HTTP 接口；`npm run test:catalog-scale` 测量目录开销并实际加载/卸载 1,001 份教学 Skill。后者的已保存结果见 `reports/capability-scale.json`。

## 数据与代码

运行数据在 `.harness/`：`sessions/` 保存快照，`events/` 保存 JSONL 原始事件，`artifacts/` 保存输出和交接记录，`workspaces/` 保存各任务示例文件，`catalog/skills/` 保留初始生成材料，`catalog/managed/library.sqlite` 保存目录、管理决定和报告，`catalog/managed/packages/` 保存带内容指纹的完整文件包版本。启动不会覆盖用户编辑过的生成文件；后续变动需要重新导入才能成为新的受管版本。数据没有自动过期清理；可停服后自行备份或移走整个目录，下一次启动会创建新目录。

```text
config/agents/       通用、分析和检查助手的配置与工作说明
server/runtime/      TS 控制器、循环、协作管理、权限范围和进程管理
server/runtime-adapter.mjs  将 TS 核心接入现有上下文、模型和任务状态
server/completion-checks.mjs  预设成果检查、文件版本与自定义检查接入
server/subagent-adapter.mjs  将协作管理接入执行、存储和结果通知
server/subagent-workspace.mjs  明确材料的复制与版本检查
server/workspace-access.mjs  请求路径及其真实目标的权限检查
server/harness.mjs    对外入口、组件组装、工具分发、授权、模型交接
server/core.mjs       取消队列、存储、路径与参数检查
server/context.mjs   上下文组装、事实保留、压缩与版本检查
server/catalog.mjs   兼容现有目录入口与初始教学样本
server/runtime/capabilities/  TS 导入、检查、目录、版本存储和独立评估
server/capability-loader.mjs  页面、模型和子助手共用的加载检查
server/capability-routes.mjs  独立能力管理 API
config/tools/        可信本机命令配置；导入文件不能自行注册可执行代码
server/models.mjs    确定性模拟器、Responses/Chat Completions 适配
server/index.mjs     HTTP API、SSE、静态页面服务
web/app/             中文交互界面
test/                自动化验证
scripts/             启动、构建、目录生成与规模验证
```

服务仅监听本机，没有多用户认证、远程部署或跨主机恢复功能。用户工作区的默认终端执行在 macOS Seatbelt 内运行；教学示例仍使用原受控进程机制。完全访问会放开文件与网络能力，不等同于容器隔离或管理员提权。

## 本轮新增示例与验证

首页展开“试试一个演示任务”，选择“隐私实体数据集”。它使用三条明确标注的合成文本，先读取规则，写入前申请授权，最后重新读取文件检查标签、Unicode 码点边界和原文一致性。`dataset.json` 与独立检查报告都可在“成果”中查看。这不是通用标注评测数据集。

自由输入在模拟模式下不会偷偷执行购物车脚本，会提示使用真实模型或预设演示。模型 A、B 的窗口和输出预留可以分别配置；容量显示为估算值，保留输出空间与估算余量。

```bash
npm test
npm run typecheck:runtime
npm run lint
npm run test:scale
npm run build
npm run build:desktop
```

宠物数据位于所选数据目录下的 `companion/`，上下文原文继续保存在任务事件与产物中。导出宠物记录不会上传数据；清空宠物记录不会清空主任务。已有 1、2 两份核心说明保持原文不变。

## 使用自己的文件

1. 添加工作区：选择本地文件夹或填写绝对路径。
2. 选择网页配置的真实模型，以及“请求批准”“帮我批准”或“完全访问权限”。权限按对话生效。
3. 描述文件任务，按需处理审批；可以随时停止。
4. 从右上角“修改记录”查看文件前后版本，撤销某一轮修改。冲突时不会覆盖用户后续修改。

修改记录使用独立本地 Git，不操作原有分支或暂存区。同一工作区暂时只允许一段对话执行；凭据、忽略文件和工作区外操作不在回滚范围内。

宠物旁边可以直接点赞、点踩、扔鸡蛋或点“太慢了”，无需展开聊天。详见 [7-模型配置、工作区权限与回滚说明](reports/7-模型配置、工作区权限与回滚说明.md)。
